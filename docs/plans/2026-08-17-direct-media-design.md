# Direct WebP/WebM media design

## Goal

Keep both the Mikluha website and the Sveltia CMS frontend deployable as static
bundles while removing build-time image downloads, resizing, transcoding and
generated variants.

## Media contract

- CMS images are WebP files no larger than 1 MiB.
- The optional home Hero background video is one WebM file no larger than 10 MiB.
- Tour and report galleries contain at most 10 images each.
- Sveltia enforces upload type and size. A deliberate hand edit of YAML may
  bypass the size limit, but source origin/prefix and file extension remain
  build invariants.
- Production CMS media uses direct HTTPS URLs under the configured Object
  Storage `cms/` prefix. Demo media uses tracked `/media/demo/*.webp` files.
- The build does not issue `HEAD` or `GET` requests for media.
- Favicon and Apple Touch Icon are one-time repository files at
  `app/favicon.ico` and `app/apple-icon.png`; they are outside CMS media and are
  never generated by a materializer.

## Rendering and fallback

Images render as native `<img>` elements without a Next.js optimizer. The Hero
always renders its WebP image as the poster/fallback. When configured, a muted,
looping, inline WebM video renders above it. The video is hidden for
`prefers-reduced-motion`, and the existing dark gradient remains above both
media layers.

## Static artifacts

`next build` produces the website in `out/`. The same export contains the CMS
frontend as static `/admin/index.html`, `/admin/config.yml` and
`/admin/sveltia-cms.js`. GitHub OAuth token exchange remains a separate broker;
neither the public site nor the CMS frontend requires a Node.js runtime.
