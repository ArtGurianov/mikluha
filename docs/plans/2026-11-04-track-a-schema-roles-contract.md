## 1. Ключевая модель

Покупается **N оценённых мест** (`seatSlotRef`) трёх типов `AGE_0_13`, `AGE_14_17`, `AGE_18_PLUS`.
Покупатель вводит только собственные данные и подтверждение возрастных условий. Туристы появляются
позже, по приглашениям, как `participantRef` конкретного места. Число мест покупки ограничено только
квотой выезда и техническим пределом запроса **500** (anti-abuse/нагрузка, не продуктовый лимит).

Документ-заказ (`orders`) остаётся носителем принятых байтов (оферта, согласие, `contract_snapshot`) и
контакта покупателя, как в 0017. Новый признак `orders.seat_model`:

| `seat_model` | Кто | Смысл |
|---|---|---|
| `UNIFORM` | все заказы до 0021 и исторический путь 0017 | `amount = unit × seats`, турист №1 = покупатель, паспорта в заказе, только взрослые. Данные и хэши не переписываются. |
| `PRICED_SLOTS` | новые native-покупки | `unit_price_kopecks` = взрослая цена опубликованной ревизии (её проверяет `contract_snapshot`), `amount` = сумма строк мест; `order_passenger` запрещён; `adults_only_confirmed=false`, `age_terms_confirmed=true`. |

## 3. Места и платёжные циклы (`seat_slot`, `seat_hold`)

Идентичность места (`seat_slot`) отделена от платёжного цикла (`seat_hold`) и от попытки оплаты
(`attempt_ref`, будущий `bankOperationRef` TOUR-77). У покупки в каждый момент не больше одного
открытого цикла; новый цикл возможен только после закрытия предыдущего без оплаты.

```
seat_hold:  OPEN ──(попытка записана до истечения 5 мин)──► FENCED ──► PAID | PAYMENT_FAILED
              └──(истёк без попытки, maintain)──────────────────────────► LAPSED
            после PAYMENT_FAILED или LAPSED → новый цикл той же покупки (fn_purchase_rehold)

seat_slot:  HELD ──(цикл закрыт PAID)──────────────────► CONFIRMED ──(только ревизия TOUR-79)──► CANCELLED
              └──(цикл закрыт PAYMENT_FAILED/LAPSED)──► RELEASED ──(новый открытый цикл)──► HELD
            RELEASED ──(поздний успех той же попытки)──► CONFIRMED, если есть место | PAID_NO_SEAT_EXCEPTION
            PAID_NO_SEAT_EXCEPTION ──(OWNER назначил место)──► CONFIRMED | ──(возврат TOUR-27)──► REFUND_SETTLED
```

| Команда | Кто (DB login) | Что проверяет БД |
|---|---|---|
| `fn_open_slotted_purchase` | `commerce_app` | свежий документ-заказ `PRICED_SLOTS`; сумма строк = `amount`; правила несовершеннолетних (раздел 6). Сама БД, по своим часам и под lock выезда: продажи открыты, выезд `OPEN` и опубликован, до T−24, есть места в квоте. Цикл 1 со сроком, который назначает БД: 5 минут, не позже T−24 |
| `fn_purchase_hold_fence(purchaseRef, attemptRef)` | `commerce_app` (TOUR-77) | открытый цикл не истёк по часам БД (2A); одна попытка на цикл; повтор той же попытки идемпотентен |
| `fn_purchase_payment_confirmed(purchaseRef, attemptRef)` | `commerce_app` (TOUR-77) | попытка записана на цикле этой покупки. Открытый цикл → `PAID`, места `CONFIRMED` (они были защищены). Цикл уже `PAYMENT_FAILED` (поздний успех) → под lock выезда каждое место `CONFIRMED` при наличии места, иначе `PAID_NO_SEAT_EXCEPTION`; решает БД, а не вызывающий. Есть более новый цикл → `NEWER_CYCLE_EXISTS` (двойное списание, ручная сверка). Покупка уже закрыта (документ-заказ `EXPIRED`, контакт удалён по 8B) → `PURCHASE_CLOSED_LATE_PAYMENT`: места не меняются, покупка не открывается, поступление — факт `bank_operation` (A2b-1), урегулирование вручную (TOUR-27). Порядок блокировок как у повторной оплаты и закрытия: выезд → строка документа-заказа → цикл → места. Повтор ничего не меняет |
| `fn_purchase_payment_failed(purchaseRef, attemptRef)` | `commerce_app` (TOUR-77) | только исход записанной попытки открытого цикла; места `RELEASED` |
| `fn_seat_holds_close_lapsed()` (maintain) | `commerce_app` | только нефенсированные циклы, истёкшие **по часам БД** (параметра времени нет: вызывающий не может досрочно закрыть живой hold); fenced (UNKNOWN) не истекает |
| `fn_purchase_rehold(purchaseRef)` через `retryNativePurchasePayment` | `commerce_app` | всё в БД, кто бы ни вызвал SQL: продажи открыты; выезд `OPEN` и опубликован; до T−24; окно повторной оплаты не истекло; строка документа-заказа заблокирована, заказ не закрыт; прошлый цикл закрыт без оплаты (нет UNKNOWN); все места `RELEASED`; квота, пауза, допуск несовершеннолетних, взрослый группы для детской покупки; срок нового hold назначает БД. TS повторяет проверки ради понятного ответа |
| `fn_priced_document_orders_close()` (maintain) | `commerce_app` | по одному документу-заказу под его строковой блокировкой (`SKIP LOCKED`) с повторной проверкой после блокировки: все места `RELEASED`, нет открытого цикла, окно повторной оплаты истекло по часам БД. Повторная оплата и закрытие заказа сериализуются на строке заказа |
| `fn_seat_slot_assign_no_seat` | `admin_app` | право `paid_no_seat.resolve` (сейчас только OWNER), причина, свободное место под lock выезда |
| `fn_seat_slot_refund_settled(slotRef, refundRef)` | `commerce_app` (TOUR-27) | только `PAID_NO_SEAT_EXCEPTION` |
| `CONFIRMED → CANCELLED` | — | функции нет ни у одного сервисного логина: только будущая ревизия поправки TOUR-79 (A2b-3) |

Триггер `seat_slot` проверяет те же правила для DML любого логина: `HELD → CONFIRMED` только при цикле
`PAID`; `HELD → RELEASED` только после закрытия цикла без оплаты; `RELEASED → HELD` только при новом
открытом цикле. Каждый переход пишет `seat_slot_event` с циклом и попыткой.

**Граница с TOUR-77.** БД связывает каждый денежный исход с попыткой, записанной на цикле, и сама
решает между `CONFIRMED` и `PAID_NO_SEAT_EXCEPTION`. Подлинность ответа банка (провайдер, сумма,
валюта, read-back) проверяет `bank_operation` TOUR-77 (A2b-1). До его интеграции эти функции —
исходники и синтетика, не квалифицированы для реальных денег.

**Время — только по часам БД.** Срок hold (5 минут, не позже T−24), истечение hold и окно повторной
оплаты вычисляются БД. Время приложения влияет только на ранний понятный отказ. В тестах время
сдвигает только суперпользователь одноразовой БД, приостанавливая триггеры; у сервисных логинов такого
механизма нет.

**Решения OWNER 06.11.2026 (1A, 2A, 2, 8B).**

- **Три срока не смешиваются.** Удержание мест — 5 минут до регистрации оплаты в банке. Банковское окно одной
  зарегистрированной попытки — 30 минут. Возобновление неоплаченной покупки — до более ранней из двух
  границ: 24 часа от создания покупки или T−24. Это окно абсолютное, попытки его не продлевают, и оно не
  является бронью мест.
- **Срок 24 часа ограничивает только начало новой попытки.** Уже зарегистрированная операция (в том числе
  UNKNOWN) обрабатывается до окончательного исхода и после этого срока и после T−24. Подтверждённый платёж
  из разрешённого окна сохраняет права покупателя. Пока операция не завершена или деньги подтверждены,
  покупка не закрывается.
- **Цена при повторной оплате — первоначальная** (`pricingBasisRef` покупки). Это не означает сохранения
  прежних условий выезда.
- **Повторная оплата не обходит изменённые условия (Stage A).** Если после принятия условий опубликована
  новая редакция выезда, новая попытка отклоняется (`DEPARTURE_CHANGED`, проверяет БД). То же при новой
  редакции оферты или согласия на ПД (`LEGAL_TERMS_CHANGED`). Эту проверку пока делает приложение:
  правовой релиз хранится в коде до TOUR-59, поэтому прямой вызов `fn_purchase_rehold` от `commerce_app`
  её не выполняет (известное ограничение Stage A). Условие подключения публичного checkout (TOUR-59/28):
  проверка выполняется внутри единого доверенного серверного пути, и ни один доступный сервису путь
  создания нового платёжного цикла её не обходит. Уже зарегистрированная попытка завершается на условиях своей
  регистрации. Сохранение первоначальной цены при повторном принятии изменённых условий — обязательное
  решение до продаж (A2b-10). До него покупателю не обещается безусловное сохранение цены при любом
  изменении выезда. Интерфейс должен объяснять причину отказа и следующий шаг, а не показывать голый код.
- **8B — удаление при закрытии.** ПД покупателя закрытой неоплаченной покупки удаляются при закрытии, без
  дополнительных суток: контакт, адрес в очереди писем, байты документов. Остаются технические
  идентификаторы, покупка, места, цены, циклы, попытки, события, платёжные доказательства и аудит; это не
  обезличивание: остаточная идентифицирующая способность и сроки хранения — TOUR-35/84. Поздний успех банка
  после закрытия места не подтверждает (`PURCHASE_CLOSED_LATE_PAYMENT`, ручное урегулирование). Закрытие невозможно при незавершённой или UNKNOWN операции,
  подтверждённой оплате или «оплате без места». legalHold останавливает удаление. Окончательная правовая
  квалификация исключений — TOUR-35/84.

## 4. Проекция занятости и счётчики (одна для TOUR-28/64/65/78/102)

`fn_departure_taken_seats(slug, now)` (заменяется в 0021, сигнатура прежняя) =
`UNIFORM`-заказы как в 0017 **+** места `PRICED_SLOTS`, у которых департамент **текущей ревизии**
покупки равен выезду и `state = CONFIRMED` или (`state = HELD` и (`payment_fenced` или
`hold_expires_at > now`)). Документ-заказ `PRICED_SLOTS` сам места не считает — двойного учёта нет.

Представление `departure_seat_projection` (без ПД), по выезду:

| Поле | Определение |
|---|---|
| `online_quota` | `departure.capacity` (онлайн-квота, TOUR-65) |
| `confirmed_seats` | `CONFIRMED` |
| `protected_holds` | `HELD` и (fenced или не истёк) |
| `paid_no_seat` | `PAID_NO_SEAT_EXCEPTION` — показывается всегда (3A) |
| `paid_seat_claims` | `CONFIRMED + PAID_NO_SEAT_EXCEPTION` — требования мест, не транзакции: депозит и доплата одного места считаются один раз |
| `over_quota` | `paid_seat_claims > online_quota` — красный 31/30; знаменатель — онлайн-квота (OWNER 04.11) |
| `online_minors_slots` | места `AGE_0_13`+`AGE_14_17` в текущих ревизиях (`CONFIRMED`/защищённые `HELD`), каждое ровно раз. Места 18+ с DOB < 18 добавит TOUR-100 (флаг анкеты, A2b) |

Инвариант штатного режима: `confirmed_seats + protected_holds ≤ online_quota`. Исключение со
«учтённым дефицитом» (v1.9 §9) — A2b для TOUR-65.

`purchase_group_projection` — по группе: выезд, покупки группы, места по типам/состояниям,
`has_active_adult` (есть `CONFIRMED` 18+). Страница покупателя видит только свою покупку.

## 6. Правила несовершеннолетних на checkout (v1.8.2 §2.1, v1.9 §3)

1. `minors > 0` требует `departure.minors_allowed` и отсутствия паузы детских продаж.
2. `departure.minor_min_age ≥ 14` исключает `AGE_0_13`.
3. Без привязки к группе: `minors > 0` требует `adults ≥ 1` в той же покупке.
4. С привязкой: допустима покупка только детских мест, если в группе есть место 18+ в `CONFIRMED`
   на том же текущем выезде (не `PAID_NO_SEAT_EXCEPTION`, не `CANCELLED`, не `HELD`).
5. Цена: `18+` и `14–17` — взрослая цена ревизии; `0–13` — `child_price_kopecks`, если задана, иначе
   взрослая. Цена фиксируется в `pricing_basis` при создании hold и далее не пересчитывается (G-09a,

## 10. Приёмка A2 (синтетика)

- 0021 применяется поверх 0020; байты и checksum 0001–0020 неизменны; `revision_hash` прежних
  `UNIFORM`-ревизий пересчитывается в тот же результат.
- G-01/G-13: покупка 5×18+, 1×0–13, 1×14–17 = 7 мест с правильными ценами одной покупкой; 12 мест
  проходят; 501 отклоняется; квота ограничивает.
- Нет ПД туристов в `PRICED_SLOTS`: вставка `order_passenger` отклоняется.
- Несовершеннолетние: отказ без взрослого; отказ при `minors_allowed=false`, паузе, мин. возрасте;
  child-only по ссылке группы — отказ без `CONFIRMED` 18+, допуск при наличии (G-GROUP-02 частично).
- Ссылка группы: чужой выезд, отозванная, израсходованная — отказ; повтор тем же ключом — та же
  покупка (G-GROUP-01 частично).
- Занятость: истёкший нефенсированный hold не считается; fenced — считается; `PAID_NO_SEAT_EXCEPTION`
  не считается, но входит в `paid_seat_claims` (31/30).
- Сопровождающий: самоназначение невозможно (только сотрудник с правом); выбытие места
  сопровождающего отзывает назначения и приглашения (G-GROUP-03 на уровне БД).
- Роли: TS = SQL-матрица; `documents.verify` только при `MODERATOR_CABINET`; отзыв возможности и
  отключение аккаунта сразу снимают права.
- Неизменяемость: `pricing_basis`, строки ревизий, журналы — UPDATE/DELETE/TRUNCATE отклоняются.
- Ревью PR #86: истёкший hold не подтверждается; новый платёжный цикл той же покупки; состав ссылки;

## 16. A2b-8 · детская цена и условия для несовершеннолетних в публикации выезда и договоре v2 (миграция 0024)

**Статус:** исходники и синтетика; 0024 не установлена ни в одну рабочую БД; продажи CLOSED. `CUSTODY_IMPACT: NO`.
Поле формы в Control Room — TOUR-64/65; показ в публичном checkout — TOUR-28.

| Требование (решения OWNER 3/6A, v1.9.1 §6, G-PRICE-PUB) | Как в БД / сервисе |
|---|---|
| Условия — часть опубликованной редакции | Документ выезда получает необязательный ключ `minorTerms` `{allowed, minAge, childPriceKopecks}`. `fn_departure_document_valid` (та же сигнатура) проверяет его при публикации: `minAge` 0–17 или `null`, цена ≥ 1 коп. или `null`; при `allowed=false` возраст и цена — `null` (не бывает «детской цены без детских мест»). Если продаются места 0–13 (минимального возраста нет или он меньше 14), детская цена указывается явно — она может совпадать со взрослой, но неявного перехода на взрослую цену нет; при минимальном возрасте 14+ детской цены нет. Нет ключа — детей не продаём |
| Единственный путь записи | Триггер `departure`: при смене `published_version` колонки `minors_allowed`, `minor_min_age`, `child_price_kopecks` копируются из опубликованной ревизии. Если они изменились, `minor_settings_version` увеличивается и пишется аудируемое событие `departure_minor_event` `SETTINGS` (автор публикации, версия выезда). Любое другое изменение этих колонок любым логином, включая владельца, — `DEPARTURE_MINOR_TERMS_PUBLICATION_ONLY`. Новая строка выезда — только значения по умолчанию |
| Пауза отдельно | `fn_admin_minor_sales_pause` (0021) меняет только паузу и версию — опубликованную сетку не переписывает |
| Договор v2 | `mikluha.order-contract/2` = схема /1 + `minorTerms`. Каждый заказ `PRICED_SLOTS` несёт /2, `UNIFORM` — /1 (`orders_contract_snapshot_model`, `NOT VALID` для строк до 0024). При вставке, под lock выезда, `minorTerms` договора должны совпасть с опубликованными условиями, а `accepted_departure_version` — с текущей опубликованной (`ORDER_MINOR_TERMS_MISMATCH`). Pricing basis в той же транзакции замораживает ту же детскую цену и её `minor_settings_version` |
| Публичная проекция | `public_departure` дополнительно отдаёт `minors_allowed`, `minor_min_age`, `child_price_kopecks`, `minor_sales_paused` (без ПД) |

**Тесты** (`test/minor-terms.test.ts`): публикация пишет, версионирует и аудирует условия, повтор тех же условий
версию не меняет, публикация без `minorTerms` снимает их; пять видов неверных условий отклоняются при публикации;
прямая запись колонок отклоняется для владельца и запрещена сервисам; пауза менеджером/снятие OWNER не меняют сетку;
публичная проекция; покупка с ребёнком несёт /2 с опубликованными условиями, basis — ту же цену и версию, сумма
верна; подмена условий в договоре сервисом или договор /1 для мест отклоняются.

**Ревью GPT PR #89 (на `ad76d13`).** Замечание P2 «детские места 0–13 разрешены без явной детской цены, места
