# Refref processing instruction — unsigned signing form

`pd-processing-instruction-refref-v1.md` is PD-REFREF-1, version 1.0, eleven sections. The accompanying
five-page DOCX is a signing form, not a signed artifact. Before signing, the owner verifies and fills
the director's name, Refref OGRNIP/address/incident contact, place/date and effective date. Have the
completed document reviewed before signing; no template constitutes a legal-compliance certificate.

The DB seed contains only its exact UTF-8 Markdown template reference/hash, `processor_ref=refref`
and `status=DRAFT`. The signed-file `sha256`, `signed_at`, `effective_at` and private-store reference
remain NULL. The DOCX and Markdown have different byte hashes; neither is a signed-file hash.
The owner records only real signed evidence after verifying the actual file in a private Russian
store. Do not publish signatures or private links. Runtime and operator have SELECT only.

Tourist PD consent stays in `content/legal/soglasie-pd.yml` and on each order independently. Neither
the processor instruction nor tourist consent is included in Refref's commercial legal-release
hash. The processor instruction permits only narrow payment/attribution data; it is not an ЕИС
mandate or UniSender instruction and does not authorize partial refunds.

- [152-FZ article 6(3): processing by instruction](https://www.consultant.ru/document/cons_doc_LAW_61801/315f051396c88f1e4f827ba3f2ae313d999a1873/).
- [Consumer law article 32: actual attributable expenses](https://www.consultant.ru/document/cons_doc_LAW_305/758e2cfdf136a621c8f66dcb3372b772c7b5e6e8/).
- [132-FZ article 10.4: ЕИС deadline](https://www.consultant.ru/document/cons_doc_LAW_12462/b887c47b3a638a8d1d38434d749a96035bc64d1b/).
