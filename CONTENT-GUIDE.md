# Памятка по управлению сайтом «Миклуха Маклай»

Весь контент сайта редактируется на странице `/admin` — отдельной админ-панели (Sveltia CMS), доступ к которой вам выдаст разработчик (нужен аккаунт на GitHub с доступом к репозиторию сайта). После сохранения изменений сайт обновляется не мгновенно — обычно в течение нескольких минут (автоматическая пересборка).

При первом входе вставьте созданный вами GitHub fine-grained token. Он должен иметь доступ только к репозиторию сайта и право `Contents: Read and write`; token остаётся в вашем браузере, его нельзя пересылать или сохранять в файлах сайта. Если вы впервые загружаете фото/файл через `/admin`, панель отдельно попросит ключ доступа к хранилищу изображений — его выдаст разработчик, он также остаётся только в вашем браузере.

**Демо-фото могут выглядеть «битыми» в панели.** Они зашиты в статическую сборку, а не лежат в медиатеке Object Storage. При первой замене фото на реальное новый файл загрузится в хранилище и будет виден в панели.

Загружайте изображения заранее в формате **WebP до 1 МБ**, видео — **WebM до 10 МБ**. CMS отклонит другой формат или файл больше лимита. В галерее тура или отчёта может быть не больше 10 фотографий; чтобы добавить новую в заполненную галерею, сначала удалите одну из существующих.

## Разделы админ-панели

- **Настройки сайта** — название, логотип, главный экран, реквизиты компании, QR/сумма бронирования и контакт по умолчанию, ссылка на MAX.
- **Туры** — направления (Алтай, Столбы и любые новые).
- **Выезды** — конкретные даты внутри направления.
- **Отчёты** — фотоотчёты о прошедших поездках.
- **Отзывы** — скриншоты переписки с участниками.
- **Организаторы** — карточка организатора (имя, фото, телефон, био).
- **Правовые страницы** — «Условия бронирования», «Политика конфиденциальности» и любые другие, которые понадобятся.

## Частые задачи

**Изменить дату выезда.** Раздел «Выезды» → открыть нужный выезд → изменить «Дата начала»/«Дата окончания» → Save changes.

**Открыть/закрыть набор.** В том же выезде — поле «Статус набора»: «Набор открыт» / «Набор закрыт» / «Поездка отменена». Отменённая поездка автоматически перестаёт предлагаться на сайте, но история сохраняется.

**Что происходит, когда выезд начался.** В ночь после дня отправления сайт сам пересобирается и убирает этот выезд из списков и из бронирования — но только если все ваши сохранённые правки уже опубликованы. Автоматика никогда не выпускает то, что вы сохранили, но не опубликовали: если такие правки есть, сайт не обновится, пока вы не нажмёте «Опубликовать изменения». Статус «Набор открыт» у прошедшего выезда всё равно стоит сменить на «Набор закрыт», чтобы данные в панели соответствовали действительности.

**Добавить новый выезд.** Раздел «Выезды» → New Выезд → выбрать направление, даты, статус → при необходимости указать свою сумму бронирования/QR/организатора (если не указывать — подставятся значения по умолчанию из «Настроек сайта»).

**Загрузить отчёт о поездке.** Раздел «Отчёты» → New Отчёт → указать направление и (если есть) связанный выезд, загрузить обложку и галерею фото.

**Добавить фоновое видео на главную.** «Настройки сайта» → «Главный экран (Hero)» → «Фоновое видео WebM». Видео необязательно: фоновое изображение всегда остаётся заставкой и запасным вариантом. Цветной затемняющий градиент сохраняется поверх видео.

**Заменить QR-код или сумму бронирования.** По умолчанию для всех выездов — в «Настройках сайта» → «Бронирование». Для конкретного выезда — прямо в документе выезда (переопределяет значение по умолчанию).

**Заменить контактный телефон.** Телефон организатора — в разделе «Организаторы». Телефон компании (для футера) — в «Настройках сайта» → «Реквизиты».

**Добавить новое направление.** Раздел «Туры» → New Тур, заполнить название, описание, фото. Новое направление появится на сайте без участия разработчика.

**Заголовки для поисковиков.** У тура есть «Название» (короткое — «Алтай», для карточек и фильтров) и «Заголовок страницы (H1)» — так, как тур ищут: «Автобусный тур на Горный Алтай из Кемерово». SEO-заголовок и SEO-описание в блоке «SEO» — то, что видно в выдаче Яндекса и Google.

**Дата существенного обновления.** У туров, выездов и отчётов есть поле «Дата существенного обновления» — по нему поисковики понимают, что страница изменилась. Новым записям оно ставится само; при заметной правке существующей (новая программа, цена, статус набора, дописанный отчёт) обновите дату на сегодняшнюю. Опечатки и мелкие правки дату не меняют.

**Короткий отчёт — скрыть от поиска.** Отчёт из пары фраз и фотографий лучше не отдавать поисковикам: включите «Скрыть от поисковых систем» — отчёт останется на сайте, но не попадёт в поиск. Подробный рассказ о поездке (маршрут, погода, что понравилось участникам, практические советы) — наоборот, полезная для поиска страница: тогда флажок снимите.

**Добавить правовую страницу.** Раздел «Правовые страницы» → New, заполнить адрес страницы латиницей — `public-offer` → страница откроется по адресу `/public-offer/` и сама появится ссылкой в футере. Разработчик для этого не нужен. «Условия бронирования» удалять нельзя — на них ссылается бронирование.

## Перед публичным запуском

Пока в «Настройках сайта» выключен переключатель **«Сайт готов к публичному запуску»**, сборка считается демо-версией. Перед тем как его включить:

- [ ] заменены тестовые реквизиты компании и телефон в «Настройках сайта» → «Реквизиты» (снят флажок «Демо-данные»);
- [ ] заменён тестовый организатор на настоящего (снят флажок «Демо-данные»);
- [ ] заменены тестовый QR-код и сумма бронирования по умолчанию (снят флажок «Демо-данные» в «Бронировании»);
- [ ] у всех выездов, отзывов и организаторов, которые должны быть видны на сайте, снят флажок «Демо-данные»;
- [ ] реальные фото и тексты вместо заглушек с надписью «ТЕСТОВОЕ ИЗОБРАЖЕНИЕ»;
- [ ] проверены тексты «Условий бронирования».

Сборка с демо-данными (`isDemo = true`) не пройдёт как публичный релиз, пока переключатель «Готов к публичному запуску» включён, — это защита от случайной публикации тестового контента.
